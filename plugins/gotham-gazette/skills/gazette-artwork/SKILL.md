# Create two separate visual stories

Read [house rules](../gazette-weekly/references/house-rules.md), the issue draft, and the verified fact packet. Use the available image-generation tool for new raster artwork and edits. Do not substitute quick programmatic SVG cartoons or stick figures for requested illustrations. Reuse approved art when Pat asks for a narrow change, preserving everything else.

Create two independent image files, never a simulated newspaper or a single combined page:
1. A front-page hero that captures the week’s strongest league narrative.
2. A political-cartoon-style commentary image about one specific league event or mistake.

Use an original comic/editorial visual language, cream/black/dark-red accents, a strong focal point, uncluttered scenes, and minimal intentional text. Personalize with relevant team labels or confirmed details. Do not center Loose Endz every week. Avoid licensed superhero imitation just because the league is called Gotham.

Generate natively large enough for the placement, aiming for at least 1400 px hero width and 1600 px cartoon width. A smaller tool output must be displayed at an appropriate size or regenerated, never merely stretched and claimed to be high resolution. Make a readable caption and descriptive alt text. Place precise statistics and important explanations in HTML so the image does not carry the only accessible copy.

Check every name, score, margin, lineup slot, injury label, caption, and visual allegation against evidence. If a named player’s status is not verified, use neutral BYE/OUT/Q categories without attaching them to that player. Do not let image generation invent news. Inspect the final image visually; correct typos and hallucinated statuses before upload. If artwork is unavailable, complete the writing and source preparation and report the asset as pending. Do not silently publish placeholders or drop the second illustration.

Upload actual files to public/ with stable issue-specific names using an available binary-safe path such as Git blob base64 with exact bytes and verified hashes. Do not paste truncated base64 through text-file tools or rely on sandbox/data URLs on the public site. Optimize into WebP or PNG as appropriate, preserve originals when useful, and check dimensions, decoding, and file sizes. Update src, social image, dimensions, alt text, and captions consistently. A generated image visible in chat is not proof of a deployed site asset.
